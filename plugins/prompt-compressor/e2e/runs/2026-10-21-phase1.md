# Phase 1 end-to-end run, 2026-10-21 (eac.15)

Run by the tests lane on the isolated dev stack (compose project pcx) built
from clean exports: core 105a0451, enterprise 813ca438, community ee47ffb
(plugin binary, new SDK, and the corpus), with `e2e/phase1.sh` and
`e2e/mockupstream` as committed with this file. The vendor is
`e2e/mockupstream` except in section 7 (real OpenAI gpt-5.5 and Anthropic
claude-sonnet-5, four requests).

## Result

**121 checks pass, 4 fail, all from one cause (eac.83):**

- A native Bedrock `converse-stream` request is compressed exactly like the
  buffered one (audit byte-identical; level 1 and level 2 equal to
  `pc-eval compress`), but it gets no `X-Tyk-Compression-*` headers and no
  record. That is the one failing row in sections 1–3 (enforce level 2, where
  the missing Tokens-Saved header is checked) and the one request missing
  from each App's record count in section 4: 38 of 39 recorded, input
  tokens short by exactly that request's 8,561. Every other request, buffered
  and streaming, matches the mock's usage to the token.

What the acceptance criteria asked for:

| Criterion | Where | Result |
|---|---|---|
| Headers on buffered and streaming responses | sections 1–3 (Stream column) | present on every OpenAI, Anthropic and Responses response, buffered and streaming; missing on Bedrock converse-stream (eac.83) |
| Recorded input tokens match the vendor's usage | sections 4 and 7 | mock: exact for every recorded request, cache-read exact; real vendors: 33,272 input / 5,760 cache-read, recorded identically |
| Estimated saved tokens in the expected range | sections 2–3 | `X-Tyk-Compression-Tokens-Saved` equals the library's own estimate for the same body on every compressed request |
| Byte-identical upstream body in audit mode | section 1 | every request |
| Enforce forwards what the library produces | sections 2–3 | every request, byte for byte |
| Uncovered paths pass through untouched | section 5 | `/ai/` and `/anthropic/` to Bedrock: upstream bytes equal at level 0 and level 2; `/ai/` to OpenAI and Anthropic: compressed (47,457 to 6,020 bytes) |
| Plugin order with Advanced LLM Cache first | section 6 | the hit is served without an upstream request and is not compressed or recorded (1 record for 2 sends); it replays the stored `X-Tyk-Compression` headers |

Other notes:

- `responses_previous_response_id` is not sent: the gateway resolves
  `previous_response_id` against the responses it served and answers 404 for
  an id it never issued, before any plugin runs.
- The `/anthropic/` bridge serves Bedrock LLMs only; an Anthropic LLM gets
  400 by design.
- Codex CLI traffic was not captured: the Codex CLI is not installed on the
  host that ran this. The corpus's Codex shapes (full history with
  `store: false` and encrypted reasoning, and a chained session) cover both
  cases in the offline replay.
- The gwbench latency half of eac.15 is on the bead (dev1).
